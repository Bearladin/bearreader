# 任务结果语义与导入书籍朗读设计

## 目标

修正任务完成状态与业务结果不一致的问题，并解决导入 EPUB/TXT 因单个 HTML 容器超过 2,000 字而触发的朗读 422。

## 任务状态

- 新增“部分完成”。完成的上级任务没有失败项时为成功，有成功项也有失败项时为部分完成，所有直接关联任务失败时为失败。
- 搜索统计只计算实际参与书名搜索的书源，不把上级调度任务或结果元数据任务算入分母。
- 单个书源正常返回零条结果属于“已完成 · 未找到”，不是访问失败。
- 搜索结果区只在搜索任务中出现；运行中、找到、未找到、结果不完整和全部失败分别显示准确提示。
- 未找到提示使用克制的语义色信息框，不增加重试、修改关键词或跳转书源按钮。
- 所有自动书名搜索失败时，提示仍可从其他书源网站取得小说目录页 URL 后提交。

## 导入书籍朗读

- 仅当小说标记为 `extra.imported=true` 且 `source_format` 为 `epub` 或 `txt` 时启用新分段。
- 导入正文按段落、列表、引用和标题等叶级块提取；图片和空块不产生朗读请求。
- 与当前章节名相同的标题节点以及 `#序号` 标题节点不重复朗读，但不修改页面内容或数据库。
- 每段优先按中文及英文句末标点切分，必要时按空白切分，最后硬切；每个请求最多 1,500 个 UTF-16 代码单元，低于后端 2,000 上限。
- 抓取小说继续使用原有顶层 DOM 子节点分段，不改变朗读行为。
- 已导入小说无需重新导入即可生效。

## 不在本批次

- 不修改 EPUB/TXT 分析、预览和确认导入流程。
- 不修改中文导出文件名；该能力已经完成。
- 不增加搜索操作按钮，不自动获取搜索结果。
- 不重构任务依赖、暂停状态或异常任务恢复。
- 不修改书源。
